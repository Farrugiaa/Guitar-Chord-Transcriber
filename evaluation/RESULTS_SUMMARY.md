## §4.2 Chord Recognition — WCSR (ChordCRNN)

**Test set:** GuitarSet Player 05 (60 clips: 30 _comp + 30 _solo)  
**Checkpoint:** `guitar_only/checkpoints/chord_recogniser_guitar.pt`  
**Metric:** Weighted Chord Symbol Recall (mir_eval majmin vocabulary)

| Metric | Value |
|--------|-------|
| Mean WCSR | **51.2%** |
| Std dev (across clips) | ± 27.4% |
| Root accuracy | 51.7% |
| Symbol accuracy | 50.5% |
| Clips evaluated | 60 |

**Breakdown by clip type:**

| Clip type | Approximate WCSR range |
|-----------|------------------------|
| _comp (chordal accompaniment) | 0.08 – 0.98 |
| _solo (melodic) | 0.11 – 0.83 |

**Key observations for §4.2:**
- High variance (σ = 27.4%) reflects genre-dependent performance: Rock/SS clips reach 0.95+; Jazz/Funk solo clips fall below 0.20
- Root accuracy ≈ symbol accuracy — model captures chord quality, not just root
- Confidence gate (threshold 0.35) is computed but no chroma fallback is available in standalone evaluation; argmax is used for all frames regardless of gate
- Median filter (k = 9) applied during inference for temporal smoothing

## §4.3 Source Separation — SDR (Demucs htdemucs vs HPSS)

**Test set:** Pilot songs (3 clips with Demucs pseudo-reference guitar stems)  
**Important caveat:** `*_guitar.wav` references are prior Demucs htdemucs outputs, **not** manual ground-truth stems. Demucs SDR is a self-consistency measure; HPSS SDR measures the quality gap between HPSS and Demucs.

| Clip | Demucs SDR (dB) | HPSS SDR (dB) |
|------|-----------------|----------------|
| Creep | 18.62 | −8.28 |
| Nutshell | 21.17 | −4.58 |
| Pearl Jam – Black | 19.56 | −4.34 |
| **Mean** | **19.78** | **−5.73** |
| Std dev | ± 1.28 | ± 2.16 |

**Key observations for §4.3:**
- Demucs self-consistency is high (~20 dB) as expected for a near-deterministic model
- HPSS SDR is **negative** on all 3 clips — the harmonic extraction is substantially dissimilar to the Demucs pseudo-reference; this should not be interpreted as absolute HPSS quality
- For a rigorous comparison, ground-truth multi-track recordings would be required
- HPSS is used as a fallback only when Demucs fails (no GPU/model load error); the pipeline always prefers Demucs

## §4.4 Tablature Transcription — Per-String Accuracy (TabCNN)

**Test set:** GuitarSet Player 05 (60 clips); audio: `audio_mono-mic/` (mic capture)  
**Checkpoint:** `guitar_only/checkpoints/tab_cnn_best.pt`  
**Note on audio domain:** Training used `audio_mono-pickup_mix/` files; evaluation used `audio_mono-mic/` files. This domain shift is a confound when comparing test vs. val metrics.

| Metric | Val split | Test split (Player 05) | Δ |
|--------|-----------|------------------------|---|
| Per-string accuracy | 93.1% | **84.1%** | −9.0 pp |
| Frame accuracy | 70.5% | **45.5%** | −25.0 pp |

Full per-clip results: `tabcnn_test_results.csv` (columns: str1–str6 = E2–e4, per_string_mean, frame_acc)

**Key observations for §4.4:**
- Per-string accuracy of 84.1% is below the 93.1% val-split figure (−9.0 pp)
- Frame accuracy drop is larger (−25.0 pp), suggesting errors tend to cluster across multiple strings simultaneously
- Two confounds for the val→test gap (discuss in §5.6):
  1. **Audio domain shift** — pickup-mix training audio vs. mic evaluation audio
  2. **Overfitting to val split** — checkpoint selected by val loss may be over-tuned to the val distribution

## Limitations

1. **No true guitar ground truth for SDR** — GuitarSet is solo guitar; pilot-song `*_guitar.wav` stems are Demucs pseudo-references. SDR numbers should be cited as self-consistency / relative quality, not absolute separation quality.

2. **WCSR confound: guitar-only vs full-mix** — GuitarSet files are isolated guitar tracks; real-world application would require source separation first, introducing additional error. The WCSR here is an upper bound on in-the-wild performance.

3. **TabCNN audio domain mismatch** — `audio_mono-pickup_mix/` (used in training) is not available locally; `audio_mono-mic/` was substituted. A fair test-set evaluation would use the same capture method.

4. **Chord vocabulary mismatch** — `ChordVocabulary(level="extended")` produces 301 classes; mir_eval WCSR collapses to majmin (25 classes). Out-of-vocabulary chord qualities map to their closest majmin equivalent.
